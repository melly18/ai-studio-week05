### 1. 위험 요소  
- api key와 db url(id와 password 모두 포함) 등 중요한 값이 모두 소스 파일에 하드코딩되었다.
- connect_db(db_url)의 line 1에서 중요 값인 db_url을 print하여 로그에 중요 값이 남도록 한다.
- request_llm_comment(summary, api_key)의 line 6에서 api 실키를 print하여 로그에 값이 남도록 한다.

### 2. 수정 사항  
- .env 파일과 python-dotenv를 사용해 중요 값을 .env에 숨기고 코드 실행 시 값을 불러오도록 수정했다. 만약 .env 파일에서 값을 불러오는데 실패했다면 RuntimeError 메시지를 통해 사용자에게 이를 알려준다.
- db_url을 print하지 않고 db 접속 시도라는 메시지만 출력되도록 수정했다. 만약 에러가 발생하더라도 권한이 있는 사람은 .env 파일을 통해 어떤 접속 시도를 했는지 확인할 수 있기 때문에 로그에 print하지 않아도 괜찮다.
- headers에서 api_key만 마스킹 처리를 해 앞 6자리만 보이도록 하여 로그에는 api 실키의 기록이 남지 않으면서 디버그 시 유용할 수 있도록 코드를 수정했다.


### 3. 1차 커밋으로 인한 실키 노출 시 올바른 대응 절차  
노출된 키를 즉시 폐기하고 새 키를 발급받는다. 새 키는 같은 실수를 반복하지 않도록 .env에 저장하고, .env가 .gitignore에 제대로 있고 커밋이나 추적되지 않는지 확인한다. 노출된 키로 인한 사용량, 청구 내역을 모니터링하고 필요하다면 사업자에 신고하는 등 적절한 조치를 취해야 한다.
